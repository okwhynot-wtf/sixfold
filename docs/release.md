# First archived release

This checklist tracks the first citable archive. The website can develop
while these items are completed.

## Content

- [x] Exact reference definition and family-selection rule.
- [x] Current results mapped to arguments and computational evidence.
- [x] Original certificates and verification data preserved.
- [x] Reproduction commands and consolidated verification runner.
- [x] Prior art and unresolved novelty question.
- [x] Credit to okwhynot-wtf and disclosure of substantial GPT assistance.
- [x] MIT for code and CC BY 4.0 for writing and images.
- [ ] Select the first public film and final caption.
- [ ] Record the film's source and rendering settings.
- [ ] Review the public technical text and resolve corrections.
- [ ] Prepare a standalone technical note from the repository sources.
- [ ] Record mathematical review status and reviewer contributions.

## Zenodo archive and DOI

- [ ] Connect the public repository to the owner's Zenodo account.
- [ ] Verify author, title, description, licences and citation metadata.
- [ ] Choose and tag the first settled version, for example v1.0.0.
- [ ] Create the GitHub release and confirm Zenodo archived it.
- [ ] Check the files available from the archive.
- [ ] Add the version DOI to the website, CITATION.cff and technical note.
- [ ] Cite that version DOI in the paper.

Zenodo assigns a DOI to each archived version and a concept DOI covering the
version history. Its GitHub integration can archive releases.
[Release guide](https://help.zenodo.org/docs/github/archive-software/github-upload/) · [Versioning](https://zenodo.org/help/versioning)

## Maintaining the record

Update [CHANGELOG.md](../CHANGELOG.md) for scientific, specification or media
changes. Reproduce affected checks. Subsequent archives should link to earlier
versions and describe corrections.
